# 아키텍처 결정 기록

## Decision (결정) 💬

프론트엔드 애플리케이션 코드를 역할과 책임에 따라  
`app`, `pages`, `widgets`, `features`, `entities`, `shared` 레이어로 분리했습니다.

전체적인 구조는 Feature-Sliced Design(FSD)의 레이어 개념을 기반으로 구성하되,  
Expo Router의 라우팅을 담당하는 `app` 디렉터리와 네이티브 구현을 위한 `modules` 디렉터리는 프로젝트 특성에 맞게 별도로 관리합니다.

## Context (배경) 🖼️

Newpic은 피드, 카메라, RTC, 사용자 인증 및 프로필처럼 서로 다른 도메인과 기능으로 구성되어있습니다.

초기 프로젝트 구조를 설계하며 `components`, `hooks`, `api`, `utils` 등 기술적인 역할을 기준으로 분리하는 방식과 FSD 기반 구조를 함께 검토했습니다.

기술 역할 중심 구조의 경우, 초기에는 단순하고 직관적이지만 기능이 늘어날수록 서로 다른 도메인이 같은 디렉토리에 얽혀  
각 코드가 어떤 기능과 도메인에 속하는지 구조만으로 파악하기 어려워질 수 있다고 판단했습니다.

따라서 코드의 기술적인 종류뿐만 아니라  
**각 코드가 어떤 기능이나 도메인에 속하고 어떤 역할을 하는지 구조에서 표현할 수 있는 방식**이 필요했습니다.

## Alternatives (검토한 대안) 📋

### 기술 역할 중심 구조

```text
src/
├── components/
├── hooks/
├── api/
├── utils/
└── types/
```

`Component`, `Hook`, `Api`, `Utility` 처럼 코드의 기술적인 역할을 기준으로 구분하는 방식입니다.

구조가 단순하고 코드의 종류를 기준으로 위치를 찾기 쉽다는 장점이 있습니다.  
하지만 프로젝트의 기능과 도메인이 증가하면 서로 다른 기능에 속한 코드가 동일한 디렉터리에 함께 모이게 되어,  
디렉터리 구조만으로 각 코드가 어떤 기능과 도메인에 속하는지 파악하기 어려워질 수 있습니다.

### FSD 기반 구조

```text
src/
├── pages/
├── widgets/
├── features/
├── entities/
└── shared/
```

`pages`, `widgets`, `features`, `entities`, `shared`처럼 코드의 역할을 레이어로 구분하고  
각 레이어 내부에서 기능과 도메인을 기준으로 슬라이스를 구성하는 방식입니다.

하나의 기능이 여러 레이어에 걸쳐 구현될 수 있다는 점은 `기술 역할 중심 구조`와 동일하지만,  
각 코드가 어떤 기능 또는 도메인에 속하며 프로젝트 내에서 어떤 역할을 하는가를 디렉터리 구조에 함께 표현할 수 있습니다.

## Reason (선택 이유) ✅

두 구조를 비교했을 때, 프로젝트 규모가 커져도 코드의 소속과 역할을 디렉터리 구조에서 파악할 수 있다는 점을 중요하게 고려했습니다.

FSD 기반 구조는 기술적인 코드 종류가 아니라 기능과 도메인을 기준으로 코드를 구성하고,  
`pages`, `widgets`, `features`, `entities`, `shared`와 같은 레이어를 통해 각 코드의 역할을 구분할 수 있습니다.

이를 통해 새로운 기능을 추가하거나 기존 기능을 수정할 때 관련 코드의 범위를 예측하기 쉽다고 판단하여 FSD 기반 구조를 선택했습니다.

## Trade-off (트레이드오프) ⚖️

- 하나의 기능이 `features`, `entities`, `widgets` 등 여러 레이어에 걸쳐 구현될 수 있어  
  관련 코드를 확인할 때 여러 레이어를 함께 살펴봐야 할 수 있습니다.
- 기능과 도메인의 역할을 기준으로 코드를 분류하기 때문에, 하나의 코드가 여러 역할과 관련될 경우  
  어느 레이어에 배치할지 경계가 모호해질 수 있습니다.

이러한 비용이 있지만, 기능이 증가하더라도 각 코드의 소속과 역할을 구조에서 파악하기 쉽다는 장점이 더 크다고 판단했습니다.

## Result (결과) 📌

현재 프론트엔드 코드는 다음 역할을 기준으로 구성되어 있습니다.

- `app`: Expo Router 기반 라우팅 및 앱 전역 초기화
- `pages`: Route에 대응하는 화면 구성
- `widgets`: 여러 Feature와 Entity를 조합한 독립적인 UI 영역
- `features`: 사용자 행동을 중심으로 한 기능과 비즈니스 로직
- `entities`: User, Feed, RTC 등 핵심 도메인 모델과 데이터 접근
- `shared`: 특정 도메인에 종속되지 않는 UI, API, Utility 및 공통 설정
- `modules`: Camera, RTC와 같이 네이티브 구현이 필요한 로컬 모듈
